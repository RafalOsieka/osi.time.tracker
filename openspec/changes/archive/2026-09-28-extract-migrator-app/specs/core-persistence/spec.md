## MODIFIED Requirements

### Requirement: REQ-039 Committed SQL migration workflow
Schema changes SHALL be expressed as SQL migration files generated by `drizzle-kit generate` from the web application's schema and committed to the repository inside the dedicated migrator application, which owns the migration history and the runner that applies it. Migrations SHALL be applied via the `drizzle-orm` migrator. The project SHALL expose `db:generate` and `db:migrate` scripts in the root `package.json`. The web application SHALL NOT contain its own copy of the migrations or a migration runner.

#### Scenario: Generating a migration
- **WHEN** a developer runs the `db:generate` script after a schema change
- **THEN** `drizzle-kit` produces a new SQL migration file in the migrator application's migrations directory that is committed to version control

#### Scenario: Applying migrations
- **WHEN** the `db:migrate` script runs against a reachable database
- **THEN** the migrator applies all pending migrations in order and records them so they are not re-applied

#### Scenario: Migration run with no pending migrations
- **WHEN** `db:migrate` runs and all migrations are already applied
- **THEN** the migrator SHALL complete successfully without making changes

#### Scenario: Existing databases keep their migration history
- **WHEN** the migrator runs against a database whose migrations were applied before the migrations moved into the migrator application
- **THEN** it SHALL recognize them as already applied and SHALL NOT re-run or fail on them
